# 夸克网盘分享页自动取消全选研究

## 结论

对页面 `https://pan.quark.cn/s/76d3b2071339#/list/share/68bc200f0d914e1ca21a8d72e47d9cf0`，最快且实测可行的方式是浏览器端 `document-start` 脚本，在表格异步加载完成后点击表头复选框。不能通过分享 API 请求参数取消全选。

## 实测基线

使用 Agent Browser 直接打开 URL，等待异步列表加载完成：

| 场景                         | readyState | checkbox 总数 | checked | `ant-table-row-selected` | 结果                           |
| ---------------------------- | ---------- | ------------: | ------: | -----------------------: | ------------------------------ |
| 无脚本，完整加载             | `complete` |            14 |      14 |                       12 | 页面默认全选                   |
| 完整加载后执行表头 `click()` | `complete` |            13 |       0 |                        0 | 当次取消成功                   |
| 取消后刷新                   | `complete` |            14 |      14 |                       12 | 被页面初始化恢复               |
| `document-start` 轮询脚本    | `complete` |            13 |       0 |                        0 | 打开后自动取消，持续观察未恢复 |

页面的 14 个复选框包括表头、12 个文件行和底部“保存为文件夹”选项；表格正文实际是 12 行。页面完全加载后，未注入脚本时全选状态会存在；只在早期的部分 DOM 上点击会被异步列表渲染覆盖。

## 原页面脚本（仅适用于行数足够的静态目录）

前一个 12 行分享页的验证脚本使用固定的 10 行门槛，只适用于该页面，不适用于少量文件目录，也不会自动处理进入子文件夹。可执行脚本已移至项目根目录的 `quark-pilot.user.js`，研究记录不重复保存代码。

原脚本实测点击发生在列表完成渲染后约 1 秒；随后至少 10 秒观察未选中状态，没有重置。固定 10 行门槛不能作为所有分享目录的通用条件。

## API、源码与失败方案

- 网络请求只有分享 token、`sharepage/detail`、`sharepage/dir` 等数据请求，没有选择状态或取消全选接口；因此改 API 请求不能改变页面勾选。
- 下载的官方页面脚本 `https://g.alicdn.com/uc-cloud-drive-web-system/cloud-drive-web/4.6.7/share.js` 长度 1,111,177 字节，源码可见 `selectedRowKeys`、`getRowSelection()` 和表头 `onChange`；选择状态由前端 Ant Design Table/Redux 本地状态维护。
- 直接修改 `localStorage.pc_share_info` 中伪造 `checkAllStatus:false` 无效；初始化仍把 `checkAllStatus` 设为真。
- 仅使用 `MutationObserver` 的方案未可靠生效，且高频全树观察可能拖慢 React 渲染；当前实现使用持续 50ms 轮询，以覆盖异步加载、目录切换和重新渲染。

## 工具限制

- Agent Browser CLI：可用，完成上述成功/失败对照实测。
- Codex 内置浏览器：能打开页面，但状态读取/截图多次超时。
- Chrome DevTools MCP：`list_pages`/`new_page` 被已有 `chrome-profile` 实例占用拦截，未能建立独立 MCP 页面；页面行为由 Agent Browser 独立复核。
- Firecrawl：可抓取运行态 HTML，显示完整加载时全选，但不适合作为精确加载时序测量工具。

## 跟进：少于 10 项与进入子文件夹

对新链接 `https://pan.quark.cn/s/82f16b845aec#/list/share/8fb6d8e197b9499c9dc0f33266bde667` 的接口和页面行为实测如下：

| 位置      |                文件树行数 | 旧脚本 `rows >= 10` | 默认状态        |
| --------- | ------------------------: | ------------------- | --------------- |
| 根目录    | 3（两个文件夹、一个文件） | 永不触发            | 表头和 3 行全选 |
| `1.0时代` |                         4 | 永不触发            | 表头和 4 行全选 |
| `2.0时代` |                         4 | 永不触发            | 表头和 4 行全选 |

接口 `sharepage/detail` 返回根目录 `_count=3`；进入 `1.0时代` 后返回 4 项。Chrome DevTools MCP 实测点击文件夹后 hash 变为 `#/list/share/5571292c7bdb45c19b5d3dbf41dd8d81`，页面重新渲染并恢复全选，说明脚本必须监听目录变化，而不是只处理首次加载。

### 修正版脚本

本节结论对应项目根目录的 `quark-pilot.user.js`，该文件是当前推荐版本；研究记录只保留行为说明，不内嵌代码。

该脚本已在根目录和 `1.0时代` 子目录实测：根目录加载约 1.5 秒后表头和 3 行均未选中；点击进入子目录后约 1.5 秒再次全部取消；随后连续采样 0、500、1000、1500、2000、2500ms 均保持未选中。

与旧脚本相比，关键变化是：取消固定行数门槛；以存在文件行作为触发条件；用目录路径、行数和行文本判断内容稳定；监听目录路由变化，进入子目录后重新处理；保留持续 50ms 轮询覆盖渲染时序和后续目录变化；检测到用户可信 checkbox 点击后，在当前目录内让用户选择接管，避免再次取消用户手动全选。
